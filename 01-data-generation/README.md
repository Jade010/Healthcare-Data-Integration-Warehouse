# 01 - Data Generation
This folder contains the scripts and output files that create the three source datasets used throughout this project. Each source is purposefully generated with data quality issues to simulation real-world challenges with data ingestion.

## Contents

```
01-data-generation/
├── README.md                 
├── generate_csv.py             ← Generates patient_claims.csv
├── generate_excel.py           ← Generates provider_directory.xlsx
├── create_lab_results.sql      ← Creates and populates dbo.lab_results in SQL Server
├── patient_claims.csv          ← Output should have 200,000 rows of patient claims data
└── provider_directory.xlsx     ← Output should have 50,000 rows of provider data
```
 
> `dbo.lab_results` lives in SQL Server and has no output file. You must run the SQL script for `create_lab_results.sql` directly against your database to populate this table.
 
## Source Datasets
 
### 1. patient_claims.csv
Generated by `generate_csv.py`. Represents insurance claims submitted by patients across multiple facilities.
 
| Column | Description |
|---|---|
| claim_id | Unique claim identifier |
| patient_id | Patient identifier |
| first_name / last_name | Patient name |
| date_of_birth | Patient DOB |
| gender | Patient gender |
| phone | Contact phone number |
| state | Patient state |
| claim_date | Date the claim was submitted |
| claim_amount | Total billed amount |
| paid_amount | Amount paid by insurance |
| claim_status | Current status of the claim |
| diagnosis_code | ICD-10 diagnosis code |
| facility | Treating facility name |
| provider_npi | Treating provider NPI |
 
**Quality issues:**
- Mixed date formats across rows (`YYYY-MM-DD`, `MM/DD/YYYY`, `YYYYMMDD`, and more)
- Gender stored as `M`, `Male`, `male`, `MALE`, `1`, `2`, `Unknown`, or blank
- Claim amounts with `$` prefixes, missing decimals, and occasional negatives
- Claim status has 10+ casing and spelling variations
- Nulls and blanks scattered across phone, state, facility, diagnosis, and paid amount
- Names in ALL CAPS, all lowercase, or with empty last names

> Note: Data is more than 25 MB and can only be accessed if you run the python script to generate it.
 
### 2. provider_directory.xlsx
Generated by `generate_excel.py`. Represents a directory of healthcare providers in the network.
 
| Column | Description |
|---|---|
| npi | National Provider Identifier |
| first_name / last_name | Provider name |
| specialty | Medical specialty |
| phone | Office phone number |
| ein | Employer Identification Number |
| zip_code | Office ZIP code |
| board_certified | Whether provider is board certified |
| telehealth | Whether provider offers telehealth |
| languages | Languages spoken |
 
**Quality issues:**
- Specialty field uses full names and abbreviations interchangeably
- Phone numbers in 5 different formats
- EIN formatted, unformatted, prefixed with `EIN:`, or missing
- ZIP codes as 5-digit, ZIP+4, truncated 4-digit, or blank
- Duplicate NPI numbers seeded in (~2% of rows)
- Boolean fields use `Y/N`, `Yes/No`, `TRUE/FALSE`, `1/0`, or blank
- Languages delimited inconsistently (`,` vs `;` vs `|`)
 
### 3. dbo.lab_results (SQL Server)
Created by `create_lab_results.sql`. Represents lab results ordered for patients, stored directly in SQL Server.
 
| Column | Description |
|---|---|
| lab_id | Unique lab result identifier |
| patient_id | Links to patient in claims |
| provider_npi | Ordering provider NPI |
| test_name | Name of the lab test |
| result_value | Test result (stored as VARCHAR) |
| result_unit | Unit of measurement |
| result_status | Status of the result |
| critical_flag | Whether result is critical |
| collected_date | Date specimen was collected |
| resulted_date | Date result was finalized |
 
**Quality issues:**
- `result_value` is `VARCHAR` — stores numerics alongside `N/A`, `PENDING`, `ERROR`, `>12`, and European decimals with commas
- `collected_date` is `VARCHAR` with 5 different date formats
- `result_status` and `critical_flag` each have 13–14 casing/spelling variations
- `result_unit` randomly NULL, lowercase, or uppercase
- ~5% of `resulted_date` values are NULL

 
## How to Run
 
### Prerequisites
```bash
pip install faker openpyxl
```
 
### Generate the CSV
```bash
python generate_csv.py
# Outputs to patient_claims.csv
```
 
### Generate the Excel file
```bash
python generate_excel.py
# Outputs to provider_directory.xlsx
```
 
### Create the SQL table
Run `create_lab_results.sql` in SSMS against your SQL Server instance.
Update the `USE HealthcareETL` line at the top if you named your database something different.
The script drops and recreates the table, so it is safe to rerun.
